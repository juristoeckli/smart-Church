# AMX Control

AMX Control is an optional Smart-Church module and is disabled by default. Installations that use AMX pull a separate AMX module image and AMX-enabled web image; standard Smart-Church images exclude the AMX server code and browser bundle. A server administrator enables the module in **Settings → Modules**; a site administrator configures the master under **Settings → Modules → AMX**. In **Settings → People & access**, a site administrator must grant **AMX room control → Use AMX controls** to each person who should see and operate the module. Site administrators can always operate it. Only site administrators can view or change controller settings. The API enforces the same grant on status and control requests, so hiding the menu is not the only access check.

The room actions use the channel mappings bundled with this integration. Enter the controller address under the AMX module settings for each installation; no site-specific IP address is shipped in the module.

The module uses the NetLinx Telnet terminal (TCP `23` by default) for channel control, held controls, active channel feedback, live levels, and activation progress. It sends `PULSE[D:P:S,channel]` for momentary controls and `ON` / `OFF` for press-and-hold controls, with a bounded release safeguard. Read-only state comes from `DEVICE STATUS [D:P:S]`; no controller configuration, authentication, or encryption settings are changed. If the controller already requires Telnet credentials, enter those existing credentials in AMX settings; the password is encrypted at rest.

Control events target port 1 of NetLinx device `34001`; the physical touchpanel is device `10001`. The controller program must declare and handle device `34001`; this module does not create or register it in NetLinx. Feedback reads the existing touchpanel device `10001` using the TP4 port and level mappings. Smart-Church page navigation stays local and never issues touchpanel page changes.

For the Steffisburg master, the touchpanel is device `10001` and the Smart-Church control target is device `34001`, both on system `1`. Home mode buttons use channels `11`–`16`. The four DSP status lamps read panel channels `21`–`24` on port `1`; the API also reads TP4 feedback ports `2`, `3`, `9`, `10`, and `13` for live channel states on the other pages. Channel and audio mappings are fixed module data sourced from the TP4 project.
