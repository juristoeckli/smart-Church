# AMX Control

AMX Control is an optional Smart-Church module and is disabled by default. Installations that use AMX pull a separate AMX module image and AMX-enabled web image; standard Smart-Church images exclude the AMX server code and browser bundle. A server administrator enables the module in **Settings → Modules**; a site administrator configures the master under **Settings → Modules → AMX**. In **Settings → People & access**, a site administrator must grant **AMX room control → Use AMX controls** to each person who should see and operate the module. Site administrators can always operate it. Only site administrators can view or change controller settings. The API enforces the same grant on status and control requests, so hiding the menu is not the only access check.

The room actions use the channel mappings bundled with this integration. Enter the controller address under the AMX module settings for each installation; no site-specific IP address is shipped in the module.

Controls use the controller WebConsole Emulate endpoint to generate NetLinx button PUSH and RELEASE events; Telnet `ON` / `PULSE` is not used because it does not reproduce touchpanel button events. Held controls remain pressed until release, with a 30-second server fail-safe. Telnet on TCP port `23` provides read-only room, DSP, volume and progress feedback. This integration does not enable or change ICSP or other controller settings. If the controller already requires Telnet or WebConsole credentials, enter those existing credentials in AMX settings; the password is encrypted at rest.

Control events target the existing virtual NetLinx device `33001`, combined with the touchpanel in the installed program. Device `34001` is not listed by this controller. The module does not create or register devices in NetLinx. Feedback reads the existing touchpanel and combined virtual device using the TP4 port and level mappings. Smart-Church page navigation stays local and never issues touchpanel page changes.

For the Steffisburg master, the touchpanel is device `10001` and the Smart-Church control target is device `33001`, both on system `1`. Home mode buttons use channels `11`–`16`. The four DSP status lamps read panel channels `21`–`24` on port `1`; the API also reads TP4 feedback ports `2`, `3`, `9`, `10`, and `13` for live channel states on the other pages. Channel and audio mappings are fixed module data sourced from the TP4 project.
