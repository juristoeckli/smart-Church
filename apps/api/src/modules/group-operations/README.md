# Group routines, certificates, and membership rules

This optional location-scoped module extends existing group and contact records. It is discovered from `manifest.json`; it does not require shared route-loader changes.

## Included

- Assign follow-up tasks to a group member with a subject, private note, due date, and optional active-member assignee. Group managers can filter by group, assignee, and status, then complete or reopen tasks; each change is audited.
- Record a meeting comment and guest count from Leader feedback. A group-specific template adds one to ten custom prompts. Group leaders and managers can save one leader response for each recorded group meeting, edit it later, see who last updated it, and export leader and attendee responses to CSV. Active group members with a linked location account can submit or update their own named response after the meeting date. Group leaders can read the submitted attendee responses; members can read only their own.
- Define active/manual, weekly, monthly, quarterly, or annual group routines; schedule dated runs, optionally assign an active group member, record notes, and complete/reopen with actor/time history.
- Define group certificates and issue records to active group members with issue/expiry dates and notes; revoke an issue with actor, timestamp, and reason. Issued/revoked records remain in history.
- Configure a reviewed membership rule based on contact status (`member` or `visitor`). Preview lists up to 500 matching people. A manager must explicitly apply a rule; each run adds up to 500 active memberships and never removes existing memberships. External-sync groups are blocked.
- Audit records for definitions, routine runs, certificate issuance/revocation, rule changes and applications, and attendee feedback submissions.

Administrative mutations require `groups_manage` or the module `manage` grant and CSRF validation. Feedback uses group-scoped permissions: active members with linked location accounts can read the template and save only their own attendee response; group leaders and managers can edit the leader response and read submitted attendee responses. Routine assignees and certificate recipients must be active members of the associated group.

## Standby restore

Site replication includes feedback templates, leader and attendee responses, follow-ups, routines, certificate records, membership rules, and audit history. Anonymous responses retain their response-token hashes and have no linked contact or account. Historical actor references are remapped to the restored account when that account is in the site snapshot.

A standby with existing Group Operations records requires a source snapshot that includes the module. Restore clears the previous site data inside the same transaction before replacing its groups, meetings, and people.

## Boundaries

- Membership rules are manually applied; there is no background evaluation, arbitrary condition builder, integration with group join requests, or membership removal. Public group join requests are handled separately by the Community module.
- Routine cadence is descriptive; runs are created by a manager and are not auto-generated by a scheduler or reminder worker.
- Follow-ups are visible only to group managers and are not delivered as email or in-app reminders. Notes have no separate private-note visibility levels.
- Attendee feedback becomes available on the meeting date. A template can require individual answers and enable anonymous submissions. There is no template version history; answers to removed or changed prompts remain stored but are not shown by the current template.
- Certificate documents/templates, signature capture, email delivery, and credential verification are not included; the module stores issue records only.
- This module does not modify contacts' core profile fields or ChurchTools/Elvanto-managed groups.
