# Group routines, certificates, and membership rules

This optional location-scoped module extends existing group and contact records. It is discovered from `manifest.json`; it does not require shared route-loader changes.

## Included

- Assign follow-up tasks to a group member with a subject, private note, due date, and optional active-member assignee. Group managers can filter by group, assignee, and status, then complete or reopen tasks; each change is audited.
- Create a group-specific meeting-feedback template with one to ten prompts. Group leaders and managers can save a response for each recorded group meeting, edit it later, and see who last updated it. Template changes retain question IDs for unchanged prompts at the same position, so matching saved answers remain linked.
- Define active/manual, weekly, monthly, quarterly, or annual group routines; schedule dated runs, optionally assign an active group member, record notes, and complete/reopen with actor/time history.
- Define group certificates and issue records to active group members with issue/expiry dates and notes; revoke an issue with actor, timestamp, and reason. Issued/revoked records remain in history.
- Configure a reviewed membership rule based on contact status (`member` or `visitor`). Preview lists up to 500 matching people. A manager must explicitly apply a rule; each run adds up to 500 active memberships and never removes existing memberships. External-sync groups are blocked.
- Audit records for definitions, routine runs, certificate issuance/revocation, rule changes, and rule application.

Administrative mutations require `groups_manage` or the module `manage` grant and CSRF validation. Meeting feedback is the exception: an active group leader/co-leader or manager can read and save that group's feedback, with the same CSRF and location scoping. Routine assignees and certificate recipients must be active members of the associated group.

## Boundaries

- Membership rules are manually applied; there is no background evaluation, arbitrary condition builder, integration with group join requests, or membership removal. Public group join requests are handled separately by the Community module.
- Routine cadence is descriptive; runs are created by a manager and are not auto-generated by a scheduler or reminder worker.
- Follow-ups are visible only to group managers and are not delivered as email or in-app reminders. Notes have no separate private-note visibility levels.
- Meeting feedback is available to group leaders and group managers only. It stores one response record per meeting, does not support attendee-submitted feedback, anonymity, required prompts, or template version history; answers to removed or changed prompts remain stored but are not shown by the current template.
- Certificate documents/templates, signature capture, email delivery, and credential verification are not included; the module stores issue records only.
- This module does not modify contacts' core profile fields or ChurchTools/Elvanto-managed groups.
