# Resource Scheduler module

This optional module extends the existing `bookable_resources` and `resource_bookings` records. It provides a weekly resource matrix, status filtering, request approval/rejection, unit counts, overlap checks with lead-in and cleanup buffers, recurring booking creation (once/daily/weekly/monthly/yearly), extra dates and skipped dates, series cancellation, and an audit endpoint. It can link bookings to appointments when the Church Calendar module is available.

The migration defaults every existing resource to one available unit and adds quantity and buffer columns to existing bookings. Resource managers can configure units and default buffers. Location scope is resolved through the module SDK; management actions accept the existing `resources_manage` permission or the module `manage` grant. Mutations require the SDK CSRF validation.

## Boundaries

- This slice creates one standard `resource_bookings` row per occurrence, so existing booking consumers can continue to read them. Recurrence metadata, extra/excluded dates, and scheduler audit history live in module-owned tables.
- Core booking routes can read the new quantity and buffer columns but do not expose recurring-series edits, appointment-link metadata, or this module's audit history. The database trigger enforces capacity and buffered conflicts on writes through the legacy booking route as well.
- New booking series snapshot the department time zone and expand recurrence by local calendar date and wall-clock time, preserving the first submitted timestamp. Legacy series without a saved zone continue using their original UTC recurrence behavior; existing bookings and overrides are not rewritten. During a spring-forward gap, a nonexistent time shifts forward by the gap (for example, 02:30 becomes 03:30); for later recurrences during a fall-back repeat, the earlier instant is selected while the submitted first occurrence keeps its exact instant. This is department-local scheduling, so a user in another time zone sees the location's clock time in the schedule.
- Recurrence expansion is capped at 500 bookings and a 12-month horizon. Owners and resource managers can preview and explicitly apply changes to future series occurrences from a chosen date, including the recurrence rule, purpose, times, quantity, and setup/cleanup buffers. Occurrences before the selected date and earlier bookings on that date remain unchanged. Applying a change updates pending rows, cancels superseded pending rows, creates new rows, checks capacity/conflicts in the same transaction, and records a detailed audit entry. Any future approved occurrence blocks the entire edit; it must be handled individually first. Existing exception dates remain in effect. Per-approved-row choices and a longer than 12-month edit horizon remain open.
- Appointment links require the optional Church Calendar schema and are managed from the scheduler. Calendar appointment changes do not automatically reschedule linked resource bookings.
- The availability configuration rejects reducing capacity below existing peak reservations. Existing resources start with one unit and need manager configuration when they represent multiple identical units.
- The series history endpoint and UI viewer are available to a series owner or resource manager.
- Owners and resource managers can override a single pending occurrence's start/end time and quantity without changing the series defaults. The override stays on the same series date, is checked by the booking capacity trigger, and is recorded in series history. A later future-series edit preserves overrides on retained dates and removes them when the recurrence drops that date. Resetting an override reapplies the current series time, duration, quantity and buffers; confirmed occurrences must be handled individually first.
- Series owners and resource managers can list and remove individual extra dates. Removing a date cancels its pending booking, removes it from recurrence metadata, records an audit row, and publishes a schedule update. An approved extra-date booking must be cancelled individually first; its occurrence history remains visible after the extra-date marker is removed.

Members and managers can mark resources on the weekly matrix and select **Marked only** to filter their schedule and printout. Marks are stored separately for each account and location.

The weekly matrix searches resource name, category, and location as well as booking purpose and requester name. Search combines with resource, status, and marked-only filters before the booking limit. Printing uses the displayed matches.

The scheduler stores the start date of new full-day requests and checks that their time interval matches that full day in the location time zone. Each repeated or extra date reserves its own location-local day, including dates with daylight-saving changes. Series owners and managers can skip dates and cancel occurrences or the series. To define a new schedule, create a new request. The weekly schedule and My bookings display them as all-day. Existing timed reservations keep their original classification. To move a full-day request, cancel it and make a new request.
