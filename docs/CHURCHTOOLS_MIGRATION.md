# ChurchTools one-time migration

The Sync settings page can create a read-only preview and import a bounded snapshot from a configured ChurchTools installation. This is a one-time import into Smart-Church; it does not write to ChurchTools or establish ongoing synchronization.

## Supported mapping

| ChurchTools source | Smart-Church destination | Mapping and behavior |
| --- | --- | --- |
| Person | Contact | Stable ChurchTools person ID is kept in the migration crosswalk. First name, last name, email, and phone are mapped to standard fields; all non-credential fields returned by the configured persons endpoint are retained as a private read-only profile, including nested and custom fields. Relationships from `GET /persons/relationships` are retained with source person IDs and relationship type metadata. When both people resolve through the crosswalk, the People directory exposes their linked relationship to users with private People access. Unresolved relationships remain in the private profile. A matching email is reported for review and is never used by itself to merge people. |
| Group | Group | Stable group ID, name, and description are mapped. Memberships link only to same-location contacts with a stable ChurchTools identity. Opt in to detailed group memberships to match shared role definitions and import the source status, entry date, and available restricted details. Existing local and manually edited membership settings are preserved. |
| Event | Service or event | Stable event ID, title, date, start/end time, all-day state, location, room, description, volunteer positions, and included time-plan items are mapped where provided. Opt in to read detailed agendas for the requested date range and link their visible items to native songs, arrangements, and unambiguous service roles. Position holders link only when their person ID resolves locally. |
| Song and arrangement | Worship song catalog | Opt in to import the permission-scoped ChurchTools catalog regardless of the event date range. The import creates native songs and arrangements and links them by stable IDs scoped to the source installation. It imports title, author, arrangement names and keys, and the default arrangement's key, tempo, and time signature when supported. A title and author match against a song without a link to this ChurchTools installation is flagged for review. Matching local arrangements without a source link are kept. |
| Resource | Bookable resource | Stable resource ID, name, supported category, description, location, capacity, approval requirement, and active state are mapped. Category values are normalized to Smart-Church's room, vehicle, equipment, or other values. |
| Resource booking | Read-only ChurchTools booking history | Opt in when previewing a migration. The selected inclusive local-date range loads pending, approved, and rejected occurrences for readable resources. Occurrences are grouped by stable booking ID. History preserves source links, recurrence and its added and excluded dates, approval status and time, quantity, and the returned occurrence dates. |
| Finance | Read-only migration preview in ChurchTools Sync settings | Select a visible source client period and an inclusive date range. Compare source account and cost-center codes and the source period dates against the local Finance setup. Review aggregate journal counts for split, tax, cancellation, immutable and transfer rows before choosing a migration approach. |

The importer preserves all non-credential fields returned by the configured persons endpoint in a private read-only profile; credential-like keys are recursively excluded. Person relationships are fetched separately and retained as profile metadata. The People API resolves imported relationships through the stable crosswalk and only returns them to users with private People access. Legacy membership history, event series/recurrence, event plans beyond the normalized fields above, and position response states remain outside the import. Unsupported agenda and nested-song field names are listed in the migration preview and counted in its unmapped-field total. Service-plan templates created in Smart-Church are local templates and do not claim a ChurchTools source ID.

Detailed group memberships use the paginated `GET /groups/{groupId}/members` endpoint and the shared role definitions from `GET /group/roles`. Active and waiting memberships map to native Active and Waitlist statuses. Requested and pending-removal memberships map to Paused and retain their exact statuses in the archive. The preview counts memberships, concealed people skipped, unknown role definitions, restricted details found, and eligible and excluded custom field values.

Site administrators can search for imported source details by group or person in ChurchTools Sync settings. The encrypted archive contains any permitted planned exit dates, remarks, waiting-list positions, status and role change dates, and registration actor IDs provided by ChurchTools. The import applies source changes to native memberships it created only while their local role, status, and entry date still match the previous import. Pre-existing memberships and later local edits are kept. Missing source rows never remove members, and reimports do not restore manually removed memberships. Scheduled sync skips membership replacement for groups with a detailed archive. Use a ChurchTools token scoped to details intended for access by Smart-Church site administrators.

Select **Archive visible custom membership fields for site administrators** to preserve source IDs, field names and types, visibility levels, and supported values for site administrators in Sync settings. Definitions and choice labels come from `GET /groups/{groupId}/memberfields` and are used only for values present in the authenticated membership response. This excludes source defaults, unselected options, person fields, application-defined API fields, and credential-like fields. The archive keeps local Group Hierarchy custom fields intact. A custom-enabled reimport refreshes the eligible values for each included group and clears archived values that are no longer visible there. A migration with the option off keeps the existing archive. Legacy membership history is excluded because its source endpoint can return historical comments and custom values beyond person and field visibility filters.

Song migration loads arrangements through the permission-scoped `GET /songs?include[]=arrangements` catalog. Chart and audio URLs already on local arrangements are preserved. Source files, links, CCLI records, tags, categories, songbook references, and arrangement-specific performance settings beyond musical key are outside this import. Run the import with a token scoped to the categories intended for the Smart-Church location's worship catalog.

Detailed agendas use `GET /events/{eventId}/agenda`. Each service plan preserves visible headers, text, and songs in source order, event-specific local start times, and notes. Positive content durations are rounded up from seconds to the nearest minute. Headers are imported without duration to avoid counting the content twice. A resolved responsibility links to a native position only when it identifies one unambiguous role in the service. Song and arrangement links use stable source IDs scoped to the installation. Include the worship catalog in the same migration to create those links for songs not yet present. A source item without a matching local song keeps its title and timing.

Detailed agenda previews are limited to 500 events per date range and 100 visible supported items per event. A missing, forbidden, or unsupported agenda leaves an existing service plan and its positions in place. Source lock state, shared agenda relationships, reusable source templates, and permission-scoped service-group notes are outside the native plan mapping.

Booking history requires location-management access. Smart-Church encrypts stored booking details and suppresses descriptions and person and appointment references for anonymized bookings. Person and appointment references are retained as ChurchTools IDs when provided. Review imported history in ChurchTools Sync settings. The archive does not reserve resources or change availability in the scheduler. Importing the same window updates matching source IDs. Importing a different window keeps a separate date-scoped record so the scope of each occurrence list stays visible. The archive retains records absent from a later response.

## Finance preview

Site administrators can open **ChurchTools finance migration preview** in Sync settings and choose a ChurchTools accounting period. The preview reads clients and accounting periods, the selected period's visible accounts and cost centers, and up to 10,000 visible journal rows for the chosen dates. ChurchTools applies period, account, and cost-center permissions. Restricted period access can produce a partial view of the source books. Preview counts reflect only the returned rows.

Smart-Church compares exact account and cost-center codes, including leading zeroes. It reports inactive, missing, ambiguous, or unsupported codes, and checks whether the full ChurchTools period matches a configured local period. The preview covers code and date matching. Journal categories can overlap and generated tax and cancellation rows count individually. The preview returns aggregate results and keeps the source and target ledgers read-only.

Use **Download account and cost-center mapping** to save a repeatable JSON review file for the selected period. It contains stable source codes and IDs, ChurchTools account group/class/type, special account flags and exact-code Smart-Church candidates. Source account types identify assets, the liabilities side of the balance sheet, or profit and loss. Smart-Church separately requires liability versus equity and income versus expense, so those rows need explicit classification review. Local type mismatches, duplicate codes, inactive candidates and missing classifications are flagged. The download reads only master data and candidate chart rows, so it does not include journal rows, amounts or donor information. [ChurchTools chart of accounts](https://churchtools.academy/en/help/churchtools-modules/master-data-finance/how-to-integrate-the-complete-skr-42-chart-of-accounts/)

With Finance enabled, site administrators can **Load master-data review** and select individual links or creations. Linking uses an active, exact-code local candidate and preserves its settings. Creating a missing account requires an explicit type consistent with the ChurchTools balance-sheet or profit-and-loss classification. Source accounts marked for opening balances, donations or configured taxes require a compatible local candidate. Creating a cost center copies its code and name. The reviewed batch is atomic, rejects changes since review, and records source installation, period and record IDs. Replaying an already-applied batch returns its original result. These links cover only master data. Journal, budget, tax, opening-balance and donor data remain outside the apply step.

The source journal models split parents, generated taxes, cancellations and cost-center transfers differently from Smart-Church's balanced posting lines. Posting, opening balances, donor and receipt migration, and changes to closed or immutable entries require a separate reconciled mapping. The source offers standard CSV/XLSX, SAGE 100, and DATEV exports. The JSON preview uses the API's structured fields in place of locale-specific export formatting. [ChurchTools transaction exports](https://churchtools.academy/en/help/churchtools-modules/import-and-export-finances-en/how-to-export-transactions/)

## Review and conflict rules

- Preview lists total/create/update/review/invalid counts and a sample of up to 40 source records. Unmapped person field names are counted; profile values are stored in the encrypted migration snapshot and then in the private ChurchTools profile. Credential-like keys are excluded recursively. The persons endpoint may return only permission-scoped fields, so this does not prove every configured ChurchTools field was returned.
- Matching uses stable source IDs. Email, group name, and event title/date/time matches are conflicts for review and are skipped during import; records are not merged on those values.
- Existing records linked by a stable ID can be updated. New migration records remain editable and are kept outside scheduled-sync cleanup.
- Group imports add source memberships only; they do not remove existing memberships.
- Paginated source lists must finish within 100 pages of 200 records per endpoint. The selected date range applies to events and, when selected, booking history. A preview can include up to 20,000 booking occurrences. An incomplete list or a booking permission error prevents that preview from being saved.

## Progress and recovery

The preview snapshot is encrypted using the server's configured encryption key. Import processes at most 50 records in a database transaction and stores its page and created/updated/skipped/failed counts. A record-level database error rolls back only that record, advances the batch, and records its area and stable source ID in the administrator-visible failure summary. Retry migration replays the same snapshot idempotently after the cause is corrected. A batch-level failure rolls back the whole transaction and does not advance the saved page. Keep the server encryption key available until the migration is complete.

Preview and import require location-management permission. Use a dedicated ChurchTools login token with only the required read access. Do not put tokens in issue comments or logs. A complete production migration should first be verified against a non-production ChurchTools site and reconciled against source counts.

## Source API

ChurchTools documents that the installed instance serves its own OpenAPI specification at `/system/runtime/swagger/openapi.json`; endpoint availability and fields can vary by installed version. Review that specification before relying on any mapping or endpoint: [ChurchTools API documentation](https://churchtools.academy/en/help/system-settings/api-en/api-documentation/). The current instance schema is at `https://gfcschweiz.church.tools/system/runtime/swagger/openapi.json`. See also the official [resource booking overview](https://churchtools.academy/en/help/churchtools-modules/resources/overview-of-resources/).
