# Interface languages

Smart Church stores a language preference on each user account. The setting follows the user across locations and sign-ins. Available choices are English (`en`), German (`de`), French (`fr`), and Italian (`it`); English is the fallback.

## Translation coverage

Localization is being rolled out by interface area. The current dictionary covers the shared navigation, Settings tabs and personal preferences (including session management), Overview, People (including the directory, add/edit form, and Elvanto read-only/import progress labels), Groups (including membership, public sign-up, join requests, and attendance), Services & events schedule browsing (including list and month views), Resources (including booking requests and approval actions), and the public group and event registration forms. Public registration pages use the visitor's browser language. Services & events create/edit, attendance, check-in, and follow-up workflows now have translated controls and labels. German, French, and Italian translations now cover common client fallback errors on Groups, Resources, Services & events, location access, signed-in sessions, and Elvanto import actions; recognized event errors and success notices are translated before they appear in global notifications. Notifications now also localize dynamic announcement counts, inbox counts, recipient addresses, read-action labels, and email-delivery statuses. Every literal error message currently returned by the Elvanto adapter routes and core server routes has a DE/FR/IT dictionary entry; errors that do not match a known phrase still fall back to English. The ChurchTools and Elvanto Sync pages have German, French, and Italian labels for the main connection, direction, permission checks, and People and Groups preview/import workflows. The one-time ChurchTools migration preview, conflict and action labels, progress, failures, retries, and known migration API errors are also translated. Server Settings now also translates the server overview, HTTP access behavior, service/build status, location management and switching, and module activation controls. Server-administrator user creation, permissions, location memberships, and password reset controls are translated. Shared module loading and failure messages are localized. File Storage includes translated labels, accessible actions, empty/loading states, and delete confirmation in English, German, French, and Italian. Remaining core pages and dynamic backend responses outside the explicit phrase maps still need translation. Built-in modules have four-language phrase dictionaries with English fallback, but their coverage and dynamic states still need a completeness review. The language selector does not mean those areas are fully localized yet.

## Adding or updating a translation

1. Add or update the English key in `apps/web/src/i18n.ts`.
2. Add the same key to all four language dictionaries in that file. The dictionaries share the English key type, so TypeScript reports a missing translation key.
3. Use the `translate` function for user-facing strings and keep each sentence as a complete translated value; do not assemble sentences from translated fragments.
4. Keep backend data, enum values, route names, and persisted values language-neutral. Translate only what the user sees.
5. Run the web TypeScript check. Review each language in the UI before marking its area complete.

Optional client modules can provide their own `translations` map on `ModuleRegistration`. Use `moduleTranslation(translations, language, key)` for module copy; it checks the selected language, then English, then the supplied fallback. The active user language is passed to module components as `ModuleContext.language`. The shared module translation host also translates matching static text and accessible labels. Chat, Community Feed, and Notifications have phrase coverage for their main workflows, notices, empty states, and common errors; dynamic server messages, authored posts, and notification content remain in the language supplied by their author. The Module Demo shows a complete English, German, French, and Italian example.
